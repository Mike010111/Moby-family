# Исполняемая спецификация прототипа

До появления бэкенда вся бизнес-логика жила в браузере: `actions.js` (редьюсеры), `store.js` и
`initial-state.js`. Теперь фронтенд работает через API (`js/core/api-store.js`), а эти файлы остались как
**спецификация поведения**: бэкенд обязан вести себя так же. `npm test` прогоняет сценарии `store.test.js`
(CI делает это в job `frontend-spec`); соответствие сценариев JUnit-тестам — в `docs/PROGRESS.md`.

Чистые правила (`js/core/rules.js`, `artifacts.js`, `catalog.js`, `format.js`) по-прежнему используются экраном
для подписей и подсказок (например, котировка перевода при вводе суммы); решения принимает бэкенд.
