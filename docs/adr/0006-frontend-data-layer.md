# ADR-006. Фронтенд: API-клиент вместо локального store

* Статус: принято
* Дата: 2026-11-08

## Контекст

Экраны прототипа читают единый объект состояния (`store.getState()`) и меняют его через
`store.dispatch('<домен>/<действие>')`, получая результат `{ ok, code, reason, … }`. Дизайн и разметку менять нельзя.

## Решение

* `js/core/api-store.js` — `ApiStore` с тем же интерфейсом (`getState / subscribe / dispatch / reset`).
  Каждый тип действия прототипа отображается на вызов REST через gateway; ProblemDetail превращается в
  `{ ok: false, code, reason }` — экраны показывают те же тексты, что и раньше.
* Состояние собирается из ответов сервисов в форме прототипа (суммы — числа, время — миллисекунды,
  статусы — в нижнем регистре), поэтому чистые функции `rules.js` / `artifacts.js` продолжают работать для
  подписей и подсказок (котировка перевода при вводе суммы, «осталось по лимиту»). Решение всегда за бэкендом.
* После операции состояние перечитывается целиком (≈10 запросов параллельно — приемлемо для стенда).
  SSE-события `notification` / `changed` запускают перечитывание с дебаунсом 150 мс.
* Изменения экранов — только слой данных: `dispatch` стал асинхронным, обработчики получили `await`,
  сканер QR принимает Promise. Разметка и стили не тронуты.
* Вкладки жюри = вход под демо-пользователем (anna / misha / ivan), токены кэшируются по вкладкам.
  Вкладка переключается только после загрузки данных нового пользователя.
* «Сбросить демо» вызывает `POST /api/<service>/demo/reset` во всех сервисах (только профиль demo).
* Прежние `actions.js`, `store.js`, `initial-state.js` и `store.test.js` перенесены в `frontend/spec/` как
  исполняемая спецификация (CI: `npm test`).

## Альтернативы

* **BFF-эндпоинт «всё состояние одним запросом»** в gateway. Меньше запросов, но gateway стал бы знать
  доменную модель всех сервисов; для демо не нужно.
* **Переписать экраны под новые DTO** — запрещено условиями и не даёт выигрыша.

## Проверка

`scripts/smoke.sh` (API) и прогон `ApiStore` против живого стенда с рендером всех трёх экранов
(см. PROGRESS: «Проверка фронтенда»).
