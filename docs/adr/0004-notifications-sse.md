# ADR-004. Уведомления: отдельный сервис и SSE

* Статус: принято
* Дата: 2026-11-08

## Решение

* notification — чистый консьюмер событий всех сервисов; тексты ленты и inbox собираются в одном месте
  (`NotificationTexts`, дословно как в actions.js), домены не знают о формулировках.
* Доставка в браузер — **Server-Sent Events** (`GET /api/notifications/stream`, `SseEmitter`): односторонний
  поток, работает через обычный HTTP и gateway, переподключение встроено в протокол.
  События потока: `notification` (новый элемент ленты/inbox) и `changed` (данные ребёнка изменились —
  перечитать балансы). Пульс-комментарий каждые 25 с.
* Отправка в поток — только после коммита транзакции (`TransactionSynchronization.afterCommit`).
* Фронтенд читает поток через `fetch` (а не `EventSource`), чтобы передать JWT в заголовке, а не в URL.

## Альтернативы

* **WebSocket** — двусторонний канал не нужен.
* **Поллинг** — проще, но задержка и лишняя нагрузка.

## Последствия / ограничения

* Подписки хранятся в памяти инстанса. При нескольких репликах notification событие обработает реплика,
  которой досталась партиция, а подписчик может быть подключён к другой. Масштабирование: отдельная consumer
  group на инстанс для рассылки (broadcast) или Redis Pub/Sub между репликами. Для демо — одна реплика.
