# ADR-010. Бесплатная витрина: GitHub Pages, GHCR, Codespaces

* Статус: принято
* Дата: 2026-11-08

## Контекст

Проверяющему нужно увидеть проект, ничего не устанавливая, и без платной инфраструктуры у владельца.
Стенд — 12 контейнеров (Postgres, Kafka, Keycloak, 5 сервисов, фронтенд, наблюдаемость): на бесплатный
хостинг он не помещается, а держать его постоянно включённым негде.

## Решение

Три уровня, от мгновенного к полному:

1. **GitHub Pages — офлайн-демо фронтенда.** Публикуется папка `frontend` как статика. `config.js`
   (`window.MOBY_CONFIG.apiBaseUrl`) в репозитории пуст, поэтому фронтенд работает на логике прототипа из
   `frontend/spec` прямо в браузере, с плашкой режима. Тот же режим включается, если адрес задан, но gateway не
   ответил на `GET /api/health` за 3 с. Все пути относительные — сайт работает по адресу
   `https://<user>.github.io/<repo>/`. Workflow `pages.yml`; там же считается бейдж покрытия
   (`badges/coverage.json` для shields.io) — отдельный сервис покрытия не нужен.
2. **GHCR — готовые образы.** `images.yml` на каждый push в `main` публикует `ghcr.io/<owner>/moby-<service>`
   с тегами `latest` и SHA коммита. В compose у сервисов и `image`, и `build`: образ берётся из реестра, а если
   его нет — собирается из исходников.
3. **Codespaces — живой бэкенд у проверяющего.** `.devcontainer` (docker-in-docker, 4 ядра / 16 ГБ) при старте
   вычисляет публичные адреса портов из `CODESPACE_NAME` и `GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN`, пишет их в
   `.env` и поднимает compose. Codespace создаётся в аккаунте проверяющего и расходует его бесплатную квоту;
   prebuilds не настраиваются — они тратили бы квоту владельца репозитория.

Адреса для Codespaces и локального запуска задаются одинаково — двумя переменными compose:
`FRONTEND_PUBLIC_URL` (CORS gateway, redirect URIs и web origins клиента Keycloak) и `KEYCLOAK_PUBLIC_URL`
(hostname Keycloak = issuer токенов, его же ждут сервисы). Без них — `localhost`, как раньше.

Фронтенд ходит к API и к Keycloak через nginx своего origin (`/api`, `/realms`). Так не нужны ни CORS, ни
публичные порты: в Codespaces все порты остаются приватными, браузер проверяющего авторизован GitHub только для
своего codespace. Gateway при этом отвечает на CORS для клиентов с других origin (`CORS_ALLOWED_ORIGINS`).

Prometheus, Grafana и Jaeger — compose-профиль `observability`: базовый стенд стартует быстрее и легче,
наблюдаемость включается одной командой.

## Альтернативы

* **Бесплатный PaaS (Render, Fly.io, Railway).** Лимиты памяти и засыпание не вмещают Kafka + Keycloak +
  5 JVM; часть сервисов требует карту.
* **Отдельный «демо-бэкенд» для Pages** — второй источник правды о поведении. Офлайн-режим использует уже
  существующую исполняемую спецификацию, которую проверяют `npm test` и JUnit-аналоги.
* **Публичные порты Codespaces** (`gh codespace ports visibility`) вместо прокси через nginx — открывали бы
  стенд всему интернету и зависели бы от прав токена внутри codespace.

## Последствия

* Офлайн-режим и бэкенд — разные реализации одной спецификации; при расхождении правды — бэкенд и JUnit.
* Образы публикуются только для `linux/amd64` (Codespaces, CI). На Apple Silicon compose не найдёт подходящий
  манифест и соберёт образы локально — это и есть запасной вариант.
* Первый старт Codespaces без опубликованных образов — сборка Maven внутри Docker (несколько минут).
