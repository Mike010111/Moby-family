# Решения

Где поведение бэкенда не следует из прототипа однозначно. Архитектура — в [adr/](adr/).

1. **Одна Postgres, своя БД и пользователь на сервис.** Изоляция данных и прав без четырёх контейнеров. На хосте —
   порт 15432 (`POSTGRES_PORT`).
2. **Ошибки.** ProblemDetail с полем `code` из прототипа; добавлены коды для отказов, которые там были без кода
   (`NOT_FOUND`, `ALREADY_PROCESSED`, `PIGGY_MAX`, `ROOM`, `IDEMPOTENCY_*`, …). Статусы: бизнес-правило — 422,
   `FROZEN` — 423, конфликт состояния — 409, ошибка ввода — 400.
3. **Тумблеры — явная установка.** `PUT …/frozen {frozen}` и `PUT …/categories/{key} {allowed}`: повтор запроса
   не переворачивает состояние обратно.
4. **Ledger.** Технические счета (эквайринг, клиринг, кэшбэк, входящие остатки) не хранят баланс — он равен сумме
   проводок, их строки не блокируются. Демо-история выписки — информационные строки, баланс открывается одной
   проводкой `OPENING`.
5. **Блокировка — явный `SELECT … FOR UPDATE` по id счетов, затем перечитывание.** `refresh(PESSIMISTIC_WRITE)` в
   Hibernate 7 читал состояние до захвата блокировки — это поймал тест на 50 параллельных оплат.
6. **Идемпотентность.** Сохраняются успешные операции и отклонённые оплаты (отказ уже записан в выписку). Отказ без
   записи откатывается вместе с ключом, повтор вычисляется заново.
7. **Кэшбэк.** Процент payment получает у rewards до транзакции (таймауты 500 мс / 1 с), чтобы не держать
   блокировку во время сетевого вызова; rewards недоступен — оплата проходит без кэшбэка. Сумма — HALF_UP до копеек,
   не меньше 0,01.
8. **Автоперевод исполняется** (в прототипе — только настройка): раз в 15 минут под ShedLock, не больше одного в
   день; неуспешный в тот же день не повторяется.
9. **Суммы во входящих запросах — строки** (`"5,25"`), как `parseMoney`: запятая, не больше двух знаков.
10. **Заморозка в family — проекция по событиям**, последняя линия защиты — payment.
11. **Копилки закрываются, а не удаляются.** При пополнении family проверяет остаток до цели, payment — деньги;
    если нарушено и то и другое, ответ `ROOM`, а не `FUNDS`, как в прототипе.
12. **P2P: нехватка денег проверяется раньше лимита** (в прототипе было наоборот): иначе подростку предлагалось
    просить одобрение на сумму больше баланса.
13. **«Доступно» в сканере QR** — баланс, урезанный остатком лимитов на все категории, а не весь баланс; сумма
    пересчитывается после каждой оплаты. Округление на фронтенде — HALF_UP, как BigDecimal на бэкенде.
14. **Офлайн-демо.** Без адреса API в `frontend/config.js` или если `/api/health` не ответил за 3 с, фронтенд работает
    на логике `frontend/spec` в браузере. Так публикуется GitHub Pages.
15. **Фронтенд ходит к API и Keycloak через свой nginx** (`/api`, `/realms`): не нужны ни CORS, ни публичные порты в
    Codespaces. Issuer токена фиксирует `KC_HOSTNAME`.
16. **`npm test` с `--no-experimental-webstorage`.** В Node 25 глобальный `sessionStorage` переносил состояние между
    сценариями прототипа.
